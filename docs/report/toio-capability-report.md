**調査日**: 2026-07-25
**対象**: toio コアキューブ（ソニー・インタラクティブエンタテインメント）
**前提**: 本リポジトリは p5.js 用ライブラリ **p5.toio** を使ったブラウザ実装

> 実装時に参照する API シグネチャ・値域・定数の一覧は [`toio-api-reference.md`](./toio-api-reference.md) にあります。本書は「何が作れるか」を判断するための読み物です。

## 3 行でいうと

1. **toio の他にない強みは「絶対座標がミリ単位で分かること」**。専用マットの上なら、キューブは自分がどこにいて何度を向いているかを常に知っている。これは他の教育用ロボットにはほぼ無い特徴で、企画の軸に据える価値がある。
2. **動く・光る・鳴る・感じる（衝突/傾き/タップ/磁石/ボタン）が一通り揃う**。ただし p5.toio から呼べる範囲はハードの全機能より狭く、**仕様書にあってもコードで叩けない機能がある**（後述）。
3. **2025〜2026 年開催の toio 公式ハッカソンは Web 上で見つからなかった**。大会固有のレギュレーションは主催者への確認が必要。本書が扱うのは一般的な開発ルール（ライセンス・仕様書の利用条件・ハード制約）まで。

## 1. toio は何ができるか

### 1-1. 動く — 座標を指定して自律移動できる

toio の移動指示には 2 つのレベルがあります。

**レベル 1: 左右のモーターを直接回す**（ラジコン的な操作）

左右のタイヤの速度を個別に指定します。前進・後退・その場旋回が作れます。`sample.js` の矢印キー操作がこれです。

- 速度の有効範囲は **8〜115**。**8 未満は無効で、キューブは動きません**。「ゆっくり動かす」を速度で表現しようとすると失敗します。
- 直進最大 350 mm/秒、回転最大 1500 度/秒。かなり速いです。

**レベル 2: 目的地の座標を渡して任せる**（自律移動）

「(x, y) へ、角度 θ を向いて行け」と指示すると、**キューブが自分で経路を作って移動します**。しかも複数の目的地を一度に最大 29 点まで渡せるため、「この順に巡回せよ」という指示が 1 回の命令で書けます。

移動の質も選べます。

| 選べるもの | 選択肢 |
|---|---|
| 移動タイプ | 回転しながら移動 / 後退せずに移動 / その場で回転してから直進 |
| 速度変化 | 一定 / 加速 / 減速 / 加減速（ease イン・アウト） |
| 到着時の向き | 絶対角度・相対角度・最短回転・回転しない など 7 種類 |

つまり「滑らかに減速しながら着地する」「バックせずに回り込む」といった**動きの表情**をパラメータで作り分けられます。ダンス・隊列・お絵かきロボットのような企画と相性が良い部分です。

> **精度の限界**: 到着とみなす閾値は座標差 15 以内かつ角度差 4 度以内。これより精密な位置決めはできません。

### 1-2. 位置が分かる — これが toio の主役

専用マットの上にいる限り、キューブは常に以下を知っています。

- **自分の絶対座標 (x, y)**
- **自分の向き（角度）**
- マットの外に出たかどうか

「ロボットが自分の位置を知っている」ことの効果は大きく、**画面の中の世界と机の上の世界を 1 対 1 で対応づけられます**。`sample.js` がやっているデジタルツイン表示（実物の位置をブラウザ上にリアルタイム描画）がまさにこれです。逆向きに、画面上でクリックした場所へ実物を走らせることもできます。

使えるマットと座標範囲は以下の通りです。

| マット | 座標範囲 | 特徴 |
|---|---|---|
| 簡易マット（本体同梱） | X: 98〜402、Y: 142〜358 | 5 行 7 列のマス目つき。**現在の `sample.js` はこれを前提にしている** |
| トイオ・コレクション 土俵面 | X: 45〜455、Y: 45〜455 | 円形の土俵、青ライン・緑ラインの判定関数つき |
| トイオ・コレクション 色付きタイル面 | X: 545〜955、Y: 45〜455 | 9×9 の色タイル。座標から色を引ける |
| 開発者用マット（A3 12 枚 / A4 10 枚） | 12 分割で最大 X: 34〜949、Y: 35〜898 | 別売。**広い空間を使いたいならこれ** |

> A4 マットは家庭用プリンタで自作印刷が可能、オリジナルデザインのオンデマンド印刷サービスもあります。

### 1-3. カードやシールを読める — 物理的な「入力」が作れる

マット以外に、**標準 ID** が印刷されたカード・シールを読み取れます。キューブをその上に置くと、どのカードかが分かります（置いた位置には依存しません）。

特に注目すべきは、**数字 0〜9、アルファベット A〜Z、記号（+ − × ÷ = ! ? % ↑↓←→）が連番 ID で揃っている**ことです。カードを机に並べて、キューブに順番に踏ませれば、**物理的に文字列や数式を組み立てる入力インターフェース**が作れます。AI と組み合わせるなら、ここは面白い切り口になりえます。

このほか、トイオ・コレクション同梱のバトルカード（13 種）、シール（6 種）、スカンク（6 色）、ゲームメニュー用マーク（25 種）にも ID が振られています。

### 1-4. 光る・鳴る

- **ランプ**: 底面にフルカラー LED が 1 個。RGB で任意の色を、明度指定つきで点灯できます。
- **サウンド**: 内蔵効果音が 11 種類（決定音・キャンセル音・マット出入り音・獲得音など）。加えて **MIDI ノート番号で任意のメロディを最大 59 音まで**鳴らせます。単音再生もできます。

> **注意**: p5.toio では**音量を指定できません**（常に最大音量）。静かな会場でのデモを想定するなら、この点は先に確認しておくべきです。

### 1-5. 感じる — 内蔵センサー

| センサー | 取れるもの |
|---|---|
| ボタン | 底面ボタンの押下 |
| 衝突検出 | ぶつかった瞬間（しきい値はレベル 1〜10 で調整可、既定 7） |
| ダブルタップ | キューブを 2 回叩いた |
| 姿勢検出 | 6 方向のどの面が上か（天面・底面・前・後・左・右） |
| 水平検出 | 水平か傾いているか |
| シェイク検出 | 揺さぶりの強さ（11 段階） |
| 磁気センサー | 磁石の装着パターン（6 種）と磁力の強さ・方向 |
| バッテリー | 残量（10% 刻み、約 5 秒間隔で通知） |

「キューブを持ち上げる」「振る」「叩く」「ぶつける」が全部イベントとして拾えるため、**画面を見ずに実物だけで完結するインタラクション**が組めます。

## 2. できないこと・気をつけること

企画を立てる前にここを読んでおくと、後から作り直す事故を減らせます。

### 2-1. 仕様書にあっても p5.toio からは呼べない機能がある

toio の BLE 仕様書には載っているのに、**p5.toio が対応していない**ものがあります。これらを前提に企画を組むと詰みます。

| 機能 | 状況 |
|---|---|
| 加速度を指定した滑らかな移動 | ライブラリ内部に「未実装」と明記されており呼び出せない |
| 傾き角度の連続取得（オイラー角・クォータニオン） | 未対応。「6 方向のどれが上か」までしか取れない |
| モーターの実測速度の取得 | 未対応 |
| サウンドの音量指定 | 未対応（常に最大音量） |
| 複数色を自動で切り替える点灯シナリオ | 未対応（自前でタイマーを組めば代替可能） |
| 各種しきい値の設定変更・スピーカー消音 | 磁気センサーの有効化以外は未対応 |

> **どうしても必要な場合**は、公式 SDK の `toio.js`（Node.js）・`toio.py`（Python）・`toio SDK for Unity` への乗り換えを検討します。いずれも MIT ライセンスで、より広い仕様をカバーしています。ただしブラウザだけで完結する手軽さは失われます。

### 2-2. 実行環境が限られる

| 項目 | 制約 |
|---|---|
| ブラウザ | **Chrome / Edge のみ**。Safari・Firefox は Web Bluetooth 非対応 |
| iPhone / iPad | **標準ブラウザも iOS 版 Chrome も不可**。Bluefy 等の専用ブラウザアプリが必要 |
| 配信 | **HTTPS または localhost 必須**。HTML ファイルをダブルクリックで開いても動かない |
| 接続操作 | ブラウザの仕様上、**ボタンを押すなどのユーザー操作からしか接続を開始できない**。ページを開いた瞬間の自動接続は不可 |

**審査員に自分のスマホで触ってもらう**ような企画を考えている場合、iPhone が事実上使えない点は早めに潰しておくべきリスクです。

### 2-3. 複数台使うときの注意

- **一括接続の仕組みが無く、1 台ずつダイアログを開いて選ぶ必要があります**。5 台使うなら 5 回クリックです。デモの導入で時間を食うので、接続手順は事前に練習しておくことを勧めます。
- **同時接続台数の公式な上限は仕様書に明記されていません**。SDK 開発元の技術ブログには 12 台程度の同時制御を検証した事例があります。多台数を前提にするなら実機で先に確かめてください。
- 会場の Wi-Fi や他チームのキューブと電波干渉する可能性があります。接続失敗・遅延は起きるものとして、リトライできる作りにしておくと安全です。

### 2-4. 電池とマット外

- **連続稼働は約 2 時間、充電は約 1.5 時間**が目安です（※販売サイト経由の情報で、公式一次資料での確認は取れていません）。長時間のリハーサルと本番が続く場合、予備の充電時間を計算に入れてください。
- **マットの外に出ると座標が取得できなくなります**。プログラム側では「座標が不明」という状態になるため、そのまま計算に使うとエラーや異常動作の原因になります。マット外に出る前提の企画なら、その扱いを最初に決めておく必要があります。

## 4. ハッカソンのレギュレーションについて

**結論から言うと、2025〜2026 年に開催される toio 公式主催のハッカソン／AI ハッカソンは、今回の Web 調査では特定できませんでした。**

確認した範囲は以下の通りです。

| 調べた対象 | 状態 |
|---|---|
| toio 公式ブログの「コンテスト」タグ | 最新投稿が **2023 年 1 月**で止まっている |
| toio 公式イベントページ（toio.io/event/） | 掲載イベントが **2021 年分のみ** |
| toio Do 作品コンテストページ | 常設ページだが**日程の記載なし** |
| 「Do!コン」（過去のコンテスト） | 2021 年春開催・終了済み |
| 2026 年開催の各種 AI ハッカソン | 複数ヒットしたが、いずれも **toio とは無関係の別イベント** |

**したがって、参加中の大会が toio 公式主催ではない可能性が高く、レギュレーション（提出物の形式・審査基準・使用可能な SDK の制限・チーム人数・開発期間など）は主催者から配布される要項が唯一の正解です。** 本書はそれを代替できません。

| トイオ・プレイグラウンド / GoGo ロボットプログラミング | 入門（カード・絵本） | 公式・本体同梱 |
| toio Do（ビジュアルプログラミング） | 初中級 | 公式 |
| toio.js（JavaScript / Node.js） | 上級 | 公式 |

## 5. 企画を考えるヒント

### 5-1. 過去のコンテストで評価された傾向

過去の toio コンテスト（Do!コン 2021、トイオの大喜利 2021〜2023）の受賞・掲載作品からは、以下の傾向が読み取れます。

| 傾向 | 具体例 |
|---|---|
| **絶対座標を活かした精密な動き** | toio でアナログ時計（針の位置を座標制御で表現） |
| **対戦・協力などのインタラクション性** | toio カードバトル、チキンレース |
| **身体を動かす体感型** | DanceDance toio!（プレイヤーの動作でキューブを操作） |
| **既存の工作物・玩具との融合** | 「動くレゴ®ブロック」「新しい工作生物」等のテーマ |

共通しているのは、**画面の中だけで完結せず、机の上の物理空間そのものを使っている**点です。toio を「画面に映すためのセンサー」ではなく「物理世界のアクチュエータ」として使う企画が評価されています。

### 5-2. AI と組み合わせるなら

toio の特性のうち、AI と噛み合いやすいのは次の 3 つです。

1. **座標が取れる = 状態を言語化できる**
   キューブの位置・向き・マット上の配置は、そのまま LLM に渡せるテキストにできます。「今キューブは (250, 250) に北向きでいる」を入力に、次の行動を LLM に決めさせる構成が素直に組めます。
2. **カードで物理的に入力できる**
   数字・アルファベット・記号のカードが揃っているため、**キーボードを使わずに文字入力する**インターフェースが作れます。「机の上に並べたカードをキューブが読み取ってプロンプトを組み立てる」といった見せ方は、AI ハッカソンでは絵になります。
3. **複数台で群れを作れる**
   各キューブが自分の位置を知っているため、協調行動・隊列・追跡が実装可能です。エージェントを複数走らせる構成の物理的な出力先として使えます。

### 5-3. 逆に避けたほうがよい企画

- **繊細な傾き制御を要するもの** — 連続的な傾き角が p5.toio から取れません。
- **音量演出が重要なもの** — 音量が固定です。
- **iPhone を配って体験させるもの** — Web Bluetooth が使えません。
- **ミリ単位の位置決めを要するもの** — 到着判定の閾値が座標差 15・角度差 4 度です。
