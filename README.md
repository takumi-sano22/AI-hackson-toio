# AI-hackson-toio

全日本AIハッカソン向けのデモ。テーマは **「友」**。
toio Core Cube 2台で鬼ごっこをしつつ、**片方が動けなくなったら助けに行き、助けたら仕切り直す**挙動をアルゴリズムで実装している。

## デモの流れ

| フェーズ | 挙動 |
| --- | --- |
| `CHASE` | 鬼は逃げ手の予測位置を追い、逃げ手は「鬼からの反発＋横への回り込み＋壁の反発＋障害物の反発」の合成方向へ逃げる |
| `CELEBRATE` | 捕まえたら勝者がファンファーレを鳴らしてその場で踊る（2台とも踊る） |
| `RESCUE` | 片方が座標をロスト（マット外）または障害物に嵌ったら、もう片方が救助に向かう。**緑=助ける側 / オレンジ=助けられる側**で点滅し、救急車のサイレンが鳴る |
| `REGROUP` | ダンスのあと・救助のあとに**それぞれの起動地点（スタート地点）へ戻って**仕切り直す |
| `HELP_NEEDED` | 救助に失敗したらピンク点滅＋呼び出し音で人の手を待つ（無限リトライで暴れさせない） |

役割交代は**捕獲したときだけ**。救助を挟んでも鬼は交代しない（救助をペナルティにしない）。

### 見やすさのための設計

- **低速で動かす**（通常 `SPEED = 35`、接近中の鬼は `NEAR_SPEED = 20`）。何をしているかを目で追えることを優先している。
- **正面衝突を避ける**。逃げ手は鬼が近いほど強く横へ回り込み、鬼は近距離で減速するため、正面から押し合って固まりにくい。
- **スタート地点は起動地点で固定**。最初に座標が読めた位置を各機のホームとして記録し、仕切り直しでは必ずそこへ戻る（画面には `START1` / `START2` の円で表示）。

## 障害物マッピング（2台の共通認識）

衝突センサー（`sensorcollision`）の検知地点と、マット上で動けなくなった（スタック）地点を **1つの共有マップ** に記録する。

- 検知したのが片方の機でも、記録先が共通なので**両機とも同じ点を避けて走る**。
- 近い検知どうしは統合し、検知回数を重ねるほど位置の推定が安定する（画面の円の中の数字が検知回数）。
- 誤検知が溜まって走れる範囲が痩せないよう、一定時間（`OBSTACLE_TTL`）で忘れる。`o` キーで手動クリアもできる。

## 実行方法

Web Bluetooth は **HTTPS または localhost でしか動かない**。`file://` で直接開いても toio に接続できない。

### p5.js Web Editor

ゲーム本体は `tag-game.js` **1ファイルで完結**しているので、そのままコピペできる。

1. 新規スケッチを作成する
2. `index.html` の `<head>` 内などに p5.toio の読み込みを1行足す
   ```html
   <script src="https://tetunori.github.io/p5.toio/dist/0.5.0/p5.toio.min.js"></script>
   ```
3. `sketch.js` の中身を全部消して、`tag-game.js` の内容をそのまま貼り付ける

### ローカル

```bash
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

## 操作

| キー | 動作 |
| --- | --- |
| `c` / 画面のボタン | toio を接続する（2台つなぐとゲームが始まる） |
| `r` | 強制的に仕切り直す（`HELP_NEEDED` からの手動復帰も兼ねる） |
| `o` | 障害物マップをクリアする（誤検知が溜まったとき用） |
| `space` | 一時停止 / 再開 |
| `f` | 全画面表示 |

パラメータ（速度・捕獲距離・検知しきい値など）は `tag-game.js` 冒頭の定数にまとめてあり、実機で調整する前提。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `index.html` | CDN 読み込みとエントリ |
| `tag-game.js` | ゲーム本体（状態機械・追跡/逃走・ロスト/スタック検知・救助・勝利ダンス・障害物マップ）。**1ファイル完結** |
| `sample.js` | p5.toio の 2D 表示サンプル（参考用。`index.html` からは読み込まない） |
| `docs/report/` | toio の実装可能な挙動・API リファレンスの調査レポート |
